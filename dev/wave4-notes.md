## W4-C: zapis dowodów ze strony (`window.__dryRelay.save`) + RUNBOOK

Problem (rundy 3 i 4): zastępcy nie mogli zapisać wyników ze strony (wyniki Apply, `actor.items`, TurnSummary, log wywołań), więc przepisywali je ręcznie do JSON-ów (literówki, ucięte listy, brak dowodu).

- W4-C-1 Relay `POST /save` (`dev/dry-run/relay.mjs`): text/plain JSON `{ token, name, content, overwrite? }` (prosty request CORS, bez preflight, jak `/requests`). Kolejność: origin (403) -> token (401) -> nazwa/treść (400) -> rozmiar (413) -> istnieje (409). Odpowiedź `{ ok, name, path, bytes, overwritten }`. Za duże ciało jest dociągane i odrzucane 413 (wcześniej `req.destroy()` dawało zerwane połączenie zamiast odpowiedzi; zmiana dotyczy też `/requests`, limit 8 MB bez zmian).
- W4-C-2 Zapis (`queue.mjs` `saveFile`): TYLKO `<DRY>\saved\<name>` (podfolder, żeby nazwa nie mogła trafić w `relay.json`, `transcript.md`, `notes.md` zastępcy); `path.resolve` + sprawdzenie `dirname === saved`; bez `overwrite === true` zapis `wx` (409 przy istniejącym), z nim tmp + rename. `.json`: obiekt -> JSON z wcięciem, string musi się parsować; `.txt`/`.md`: string bez zmian. Limit 2 MB liczony na bajtach UTF-8 tekstu zapisywanego.
- W4-C-3 Nazwa (`checkSaveName`): `^[A-Za-z0-9._-]+\.(json|txt|md)$`, max 100 znaków, bez kropki na początku, bez `..`, bez nazw urządzeń Windows (`CON.json`, `nul.txt`, `com1.md`), rozszerzenie małymi literami.
- W4-C-4 Pomocnik strony (wybór: w wyjściu `driver.mjs snippet`, nie w kodzie modułu; `dry-transport.mjs` i `builder-api.mjs` bez zmian). `snippet` drukuje 3 części: 1 włączenie (jak dotąd), 2 linia pomocnika, 3 wyłączenie; `driver.mjs helper` drukuje samą linię. Źródło z `pageHelperSource()`: bez tokenu (czyta relay i token z wartości `moinens-ai-gen.build.dry` w localStorage), rzuca błąd poza hostem loopback / portem toru / na :30000, bez konfiguracji dry i przy złym adresie relay; `save` odmawia, gdy `api.build.dry` jest null. Pomocnik żyje tyle co strona: po każdym przeładowaniu trzeba go uruchomić ponownie (RUNBOOK krok 4.6).
- W4-C-5 `driver.mjs status` ma pole `saved` (lista plików).
- W4-C-6 RUNBOOK: twarda zasada „dowody tylko ze strony przez `save`, nigdy przepisane; notatki i odpowiedzi to jedyne pliki pisane ręcznie”; krok 4.6 (pomocnik + `start.json` jako test i zapis toru); sekcja „Saving evidence” (nazwy, 2 MB, overwrite, kody błędów, sprawdzanie z zapisanego pliku); 6a krok 3 zapisuje `apply-<tura>.json` z CAŁYM wynikiem (`result`), `input`, `first` (odrzucone pierwsze wywołanie), `items`; `snapshot-<tura>.txt` i `snapshot-final.txt`; `turns.json` i `calllog.json` z `overwrite: true`; raport wymienia `<DRY>\saved\`, wynik niezapisany = „niezweryfikowany”.
